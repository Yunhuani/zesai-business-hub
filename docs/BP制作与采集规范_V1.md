# 商业计划书（BP）制作与采集规范 · V1.0

> 本规范是「商业计划书」这一交付物的统一标准，是 BP Agent 开发的**唯一业务依据**。
> 地位等同于 NBG 的《采集输入需求清单》+《诊断报告制作规范》合体。
> 涉及业务判断（采集什么、产出什么、长什么样）一律以本规范为准，不自行发挥。
>
> 编写依据：创始人 BP 八步法方法论 + 线下《商业计划书撰写资料清单》+ 泽思AI 产品定位。
> 版本 V1.0，2026-08。

---

## 一、总纲（BP Agent 的定盘星）

> **BP 引擎 = 投资人视角的 BP 结构化专家。**
> **核心价值：把客户零散的信息，用结构化、模块化的方式，整合呈现成一份面向投资人的专业商业计划书。**
> **搜索仅作有限补充，且不保证正确、必须标注。BP 不是信息搜集工具——信息搜集是其他 Agent 的职责。**

这句话是 BP 所有设计的源头，任何模块设计、prompt、页面若与之冲突，以本总纲为准。

**三个关键定性（不可动摇）：**

1. **我们的价值是"结构化呈现"，不是"市场调研"。** 客户要做 BP，本就该手握这些信息。我们的本事是用八步法方法论 + 投资人视角，把零散信息升维成一份会讲故事、逻辑严密的投资级 BP。
2. **不以信息搜集为主业。** BP 允许在限定范围内做有限搜索（见红线3），但不以"帮客户查全数据"为卖点或承诺——别让客户以为 BP 是个调研工具，那会窄化产品、也无法兑现。搜索只在客户信息明显缺失或存疑时做补充旁证，且标注"需验证"。信息搜集本身是其他 Agent 的职责。
3. **信息由客户提供、责任由客户承担。** 必填信息客户必须自己填，数字是客户写的，最终结果由客户负责。我们不替客户编造，也不为数据准确性背书。

## 二、三条贯穿全局的红线（护城河的技术保障）

BP 的每个模块设计、每条 prompt、每处生成，都必须同时守住以下三条。这是 BP 版的"三红线"，与 NBG 红线同源。

### 红线 1 · 改写权（表达可升维）

引擎**必须**用专业咨询口吻改写客户原话，把口语化、零散的表述，升维成投资人视角的专业表达。这是 BP 专业感的来源，也是"客户拿豆包做不到"的价值体现。

- 示例：客户写"现在工厂招工太难了，人越来越贵" → 引擎产出"制造业用工成本持续攀升、招工难加剧，倒逼企业寻求自动化替代方案——这是一个由结构性劳动力变化驱动的刚性需求。"

### 红线 2 · 有根扩充，不凭空编造

这是 BP 最核心的一条，决定了"专业饱满"和"投资人一眼识破"的分界。

**核心原则：引擎可以充实、扩展、图形化，让每页信息完整专业；但所有增加必须"有根"——基于客户提供的原有内容，或搜索能找到的带源内容。绝不无中生有。**

**✅ 允许的"有根扩充"（引擎应主动做，让页面饱满）：**

- **表达升维**：客户口语 → 咨询口吻专业表述（红线1）。
- **框架化展开**：把客户给的要点，用咨询框架讲透（如痛点 → 为什么刚需 → 影响面），逻辑是客户的，只是展开论证。
- **图形化呈现**：把信息做成图/表/矩阵/时间轴，信息量不变、呈现更专业、自然撑起版面（见第五节）。
- **结构补全**：客户漏了某个该有的分析角度，引擎按框架补上结构性栏目并引导。
- **带源搜索补充**：市场、竞品公开信息可搜（红线3），标注来源 + "需验证"。

**❌ 禁止的"无根编造"（守死，绝不放开）：**

- **不改数**：客户说"用户 5000"，绝不写成"用户近万"。
- **不编数**：客户没给、也搜不到的具体数字，绝不凭空生成（如自己填一个"市场约 50 亿""毛利率约 60%"）。
- **不虚构事实**：不编造客户没有的用户数、合作方、业绩、履历。
- **确实缺失且无从补**：标注**"待补充"**，提示客户补料，绝不靠编数字/套话注水。

**一句话：充实"表达和呈现"——放开；编造"事实和数字"——守死。页面的"满"靠图表和把逻辑讲透实现，不靠编内容。**

本条等同 NBG 第一红线"财务数字必须代码算、大模型不新增数字"。BP 里凡具体数字，来源只有两个：客户提供、或搜索带源（标注需验证）。引擎自己**不生产无根的数字和事实**。

### 红线 3 · 搜索边界（仅补充、必标注、不覆盖）

- **可搜索的仅两处**：模块3（市场规模的行业公开数据）、模块4（竞品的公开信息）。其余模块一律不搜。
- **搜索结果必须**：标注来源 + 标注"需验证"；与客户数字**并列呈现**，不替换、不覆盖客户提供的数字。
- **搜索是配角**：仅在客户信息缺失或明显不合理时触发做旁证，不是每次必跑，更不是数字主来源。

## 三、文档整体结构与交付形式

### 交付形式（定案）

**BP 最终交付一个 PDF 文件。**

- 技术路径：HTML/CSS 渲染页面 → 打印为 PDF，**复用 NBG 现有的 Puppeteer 打印管线**（引擎结构化输出 → React/HTML 页面 → Puppeteer → pdf-lib 合并封面 → 压缩）。
- 选择 PDF 而非程序生成 PPT 的原因：①HTML/CSS/SVG 设计自由度高，程序生成的 PPT 做不出所需的信息图精度；②PDF 渲染一致，PPT 在不同版本 Office/WPS 上易错位，发给投资人风险高；③复用现成管线，零额外技术引入。
- PDF 同时满足"文件形式"的全部诉求：可下载、可发送、可打印存档、可全屏放映当路演材料。
- **可编辑需求**：PDF 不可改是唯一短板。解决方式为"平台内修改内容后重新生成"，不导出低质量 PPT。

### 页面结构

BP 是给投资人看的成品，不是八块内容的堆叠。完整结构如下：

| 顺序 | 部分 | 说明 |
|---|---|---|
| 1 | **封面** | BP标题、公司名、slogan、日期 |
| 2 | **Executive Summary（执行摘要）** | 全篇最重要一页，见下方专述 |
| 3 | **八模块正文** | 模块 0–8，见第四节 |
| 4 | **封底** | 联系方式 |

### Executive Summary 专述（全篇最重页）

- **地位**：投资人往往先看它、甚至只看它。这页做不好，后面的内容投资人不会翻。
- **内容**：把八模块的钩子浓缩成一页的"投资故事精华"——做什么、解决什么刚需、市场多大、凭什么赢、要多少钱。
- **生成时序**：**逻辑上最后生成**（八模块全部产出后，回头提炼），**位置上放最前**。类似 NBG 综合环节从五维里提炼三大发现的做法。

## 四、八模块 Schema

每个模块定义三样：**采什么**（向客户对话式采集）、**产出什么**（引擎生成进 BP 的结构化字段）、**来源标记**（客户提供 / 可搜索 / 引擎改写）。

**本版原则：采集信息全部必填**（极少数锦上添花项除外，如网站/公众号）。数字客户自己填、自己担责；引擎不得遗漏该问的。

### 模块 0 · 项目概况

- **采什么**：BP标题（客户给，或授权引擎生成）、公司名称、成立时间、主营业务（一句话）、人员状况（人数/组织结构）、网站/公众号（选填）、slogan
- **产出**：`bp_title`、`company_name`、`founded`、`one_liner`、`business_summary`、`team_scale`、`slogan`
- **来源**：全部客户提供；`bp_title` 与 `slogan` 引擎做投资级表达加工（改写，不改事实）

### 模块 1 · 需求（Why — 解决谁的什么痛点）

- **采什么**：目标用户/客户是谁、有什么特点；最主要的三个痛点
- **产出**：`target_customer`（客群画像）、`pain_points`（三大痛点，每个含"痛点描述 + 为什么是刚需"）、`why_now`（可选，窗口期判断）
- **来源**：痛点客户提供；引擎的价值是把痛点**论证成"刚需"**（八步法"找刚需"的魂）。`why_now` 若引擎补充则标注"待验证"

### 模块 2 · 产品与模式（How）

- **采什么**：针对三大痛点分别怎么解决；核心价值/特点三点；盈利模式（收入来源/毛利率/净利率/各来源占比）；销售模式（渠道/特殊资源）
- **产出**：`solution`（与模块1痛点一一对应）、`core_value`、`business_model`、`sales_model`
- **来源**：全部客户提供。**数字（毛利率/净利率/占比）锁死**，缺则标"待补充"；表达可改写

### 模块 3 · 市场规模（Where — 数字密集，红线重点）

- **采什么**：市场规模预估 + 未来 3–5 年增速（客户预估数）；客户判断依据
- **产出**：`market_size`（TAM/SAM/SOM + 3–5 年规模/增速表）、`market_narrative`（为什么这市场值得投）、`market_validation`（搜索旁证）
- **来源**：
  - 客户预估数字：**主来源，原样保留**
  - 搜索补充（本模块是搜索的合法落点之一）：**标注来源 + "需验证"，与客户数字并列，不覆盖**
  - 客户没给且搜索不确定：标"待客户补充/进一步验证"，**不硬编**

### 模块 4 · 竞争分析（Which）

- **采什么**：竞争对手（A/B/C/D）；各维度对比（产品/技术/团队/渠道/其他）；我方核心优势三点
- **产出**：`competitors`（竞品矩阵）、`differentiation`（差异化/稀缺性论证——八步法"稀缺性"的魂）
- **来源**：客户提供为主；竞品**公开信息**引擎可搜索补充（标注需验证，本模块是搜索第二个合法落点）；优势论证引擎改写升维

### 模块 5 · 目前状况（用数字）

- **采什么**：产品功能进展、用户/客户数（数量/日活/月活）、市场覆盖（地域/行业）、财务（收入/利润）、团队规模、媒体/合作/评价
- **产出**：`traction`（现状实绩，数字原样、表达改写）
- **来源**：全部客户提供；**数字锁死不改不编**，缺则标"待补充"

### 模块 6 · 未来规划（里程碑 + 财务预测）

- **采什么**：市场发展预期（含地域扩张）、产品规划、用户增长预估、财务预测（3–5 年收入/净利润）
- **产出**：`roadmap`（里程碑）、`financial_projection`（3–5 年预测表）
- **来源**：客户提供；**预测数字原样保留**；引擎可对"合理性叙述"做加工，不改数字

### 模块 7 · 融资计划

- **采什么**：计划融多少钱、计划稀释比例（区间）、资金用途及占比（产品开发/市场拓展/团队建设/其他）
- **产出**：`funding_ask`（融资额 + 稀释）、`use_of_funds`（资金用途结构）
- **来源**：全部客户提供，数字锁死

### 模块 8 · 团队（Who）

- **采什么**：核心成员——照片、姓名、职务、过往经验（按线下清单格式）
- **产出**：`team`（成员卡片，背景按投资人视角提炼，突出与项目相关的经验背书）
- **来源**：客户提供；引擎做"经验背书"的表达强化，**不编造履历**

## 五、页数与版面

- **总量**：16–20 页弹性区间。20 页左右为宜，**不少于 16 页**。
- **弹性分配**：引擎按每模块内容量在给定范围内自动决定占几页。钩子模块（需求/市场/竞争/融资）可多给，信息型模块（概况/现状/团队）紧凑。
- **页面饱满与图形化是引擎的明确职责，不是可选项。** 每一页都应信息完整、专业、图文结合，不留空洞开天窗的页面。达成方式是"有根扩充"（红线2）+ 图形化，**不是文字注水**。
- **页数下限的达成方式（重要）**：靠**图表化 + 重点模块深展开**撑页，**严禁文字注水**。
  - 图表化（应尽职责）：市场规模出图、竞争出矩阵、财务预测出表、里程碑出时间轴——一个信息点用可视化承载，既专业又自然占版面。（延续 NBG"严禁满页文字、图形化承载逻辑"）
  - 框架化展开（应尽职责）：把客户给的要点用咨询框架讲透，让页面内容完整，逻辑有据。
  - 若信息实在不足、图表也撑不满 16 页：**提示客户补充关键信息以增强说服力，允许特例低于 16 页，绝不靠套话注水或编造内容凑数**。

### 页数分配参考（弹性，非死值）

| 部分 | 参考页数 |
|---|---|
| 封面 | 1 |
| Executive Summary | 1 |
| 模块0 项目概况 | 1 |
| 模块1 需求（钩子） | 1–2 |
| 模块2 产品与模式 | 2 |
| 模块3 市场规模（重点） | 1–2 |
| 模块4 竞争与差异化（重点） | 1–2 |
| 模块5 目前状况 | 1 |
| 模块6 未来规划 + 财务预测 | 1–2 |
| 模块7 融资计划（重点） | 1 |
| 模块8 团队 | 1 |
| 封底 | 1 |

合计浮动约 14–18 页，卡在 16–20 目标区间内、留弹性。

## 六、质量基准线

一份合格的 BP 必须同时满足：

1. **结构化**：八模块 + 封面/Executive Summary/封底 齐全，逻辑自上而下成一条投资故事线。
2. **专业表达**：客户原话经咨询口吻改写升维，无口语化、无零散感。
3. **事实可信、有根扩充**：所有内容基于客户提供或带源搜索，可充实展开、图形化，但无凭空编造；搜索补充项均标注"需验证"；确实缺失且无从补的，标"待补充"而非注水或编造。
4. **投资人视角**：每模块回答投资人真正关心的问题（是不是刚需、市场够不够大、凭什么是你、要多少钱怎么花、团队靠不靠谱）。
5. **图表化**：关键逻辑用图/表/矩阵/时间轴承载，非满页文字。
6. **Executive Summary 立得住**：一页讲清整个投资故事，能独立打动投资人。
7. **页数达标**：16–20 页，靠有料内容和图表达成，非注水。

## 七、视觉与版式规范（V1.1 补充，2026-08 定案）

本节为三方视觉对照测试（自研 / CyberPPT / Claude Design）后的定案，是 BP 模板开发的视觉基准。

### 7.1 技术路线：自研模板，纯矢量

**BP 视觉走自研 HTML/CSS/SVG 模板渲染，不调用第三方生成工具。**

对照测试结论：

| 方案 | 视觉水准 | 图表信息化 | 数据可信 |
|---|---|---|---|
| CyberPPT（生图路线） | 88–90 | 强 | **会编造数据，致命** |
| 自研模板 | 84–86 | 强 | 不编造 |
| Claude Design | 75–78 | 弱（近乎纯文字） | 不编造 |

- **CyberPPT 不可用于自动产品线**：实测中它虚构了真实企业名作为合作方、编造了 NPS/成本/毛利等客户未提供的数字，直接违反红线2。其"人在环中逐页生图确认"的流程也与自动化 SaaS 形态不匹配。可保留为**人工层精修工具**（服务高价值客户），不进自动产品线。
- **视觉差距的根源是缺真实图片，不是设计能力**——两条独立的 AI 设计路径撞在同一限制上。**学 CyberPPT 的设计语言，不学它的编造。**

### 7.2 设计语言

- **配色**：藏青 + 亮蓝为主基调（商务科技感，贴投资场景），取代早期黑金方案。
- **结论收口**：每页底部深色条，**直接放那句结论本身，不加"SO WHAT"或任何中英文标签前缀**。
- **信息图（核心）**：严禁满页文字，逻辑一律用图形承载。已验证有效的图式：
  - 痛点 → 损失机制**四步传导链**
  - 竞争 → **评分点阵矩阵**（圆点表示适配度）+ 我方列高亮
  - 市场 → **阶梯式 TAM/SAM/SOM 漏斗**
  - 增长 → 柱状图 + **增速气泡标签**
  - 财务 → 双序列柱状 + **盈亏平衡点标注**
  - 规划 → 三阶段时间轴　融资 → 环形图 + 用途明细
  - 摘要 → 四栏结构（问题 / 方案 / 牵引 / 融资）+ 关键指标卡
- **关键数字**做大字视觉锤；增长语义用正向色表达。

### 7.3 配色主题（差异化机制）

**通过配色主题切换解决"不同客户 BP 千篇一律"的问题**——变化由客户主动选择，范围预先设计，既差异化又可控（不像生图路线会失控漂移）。

第一版提供四套，选择时标注适用场景：

- **浅底系**（适合打印、传统行业）：藏青商务（默认）、墨绿金
- **深底系**（适合屏幕演示 / 路演、科技行业）：深空蓝、曜石金

> 产品提示：选择界面应提示"深色适合屏幕演示，浅色更适合打印"——BP 客户常需打印纸质版，深色满版极费墨且打印效果差。

版式变体、封面样式变体等更大范围的差异化，列为二期。

### 7.4 防溢出机制（必做，不可省略）

样例测试中已实测暴露：内容超出 16:9 固定框会导致**元素重叠、文字截断、排版挤压**。手工内容尚且溢出，**引擎自动生成时客户内容长短差异更大，溢出将成为常态**——客户收到一份文字被截断的 BP 是产品事故。

模板开发必须包含三层防护：

1. **引擎侧**：每个字段设定字数范围约束，从源头控制内容长度。
2. **模板侧**：每个区块设最大高度 + 超出降级策略（缩小字号 / 截断省略 / 自动分页）。
3. **渲染后**：溢出检测，发现超框自动调整或告警，不允许带病交付。

### 7.5 AI 生图（二期增强，第一版不做）

自研纯矢量的视觉上限约 84–86 分；余下差距来自实拍级配图，纯矢量无法弥补。

**第一版不接生图**，原因：
- 国内可商用生图服务需单独选型接入；
- 生成不可控，出一张怪图比没图更糟，需额外的筛选/重试机制；
- 增加生成耗时与成本，影响体验与毛利；
- AI 生成图用于客户正式融资材料的权责需厘清。

**二期考虑**：仅在封面、产品架构页、封底 3–4 个关键位置生图，成本可控且视觉提升最明显。是否投入，以第一版上线后的真实客户反馈决定。
